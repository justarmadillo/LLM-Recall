# LLM Recall Handoff

This document is for another engineer or LLM taking over the project. It explains the app shape, the major code paths, what is intentionally local-only, and how to verify changes.

## Product

LLM Recall is a local flashcard review app for CSV decks generated by LLMs or other sources. It can also act as a pre-Anki staging area by exporting kept cards back to Anki-ready CSV.

Core behavior:

- Import CSV from a file, pasted text, Android file-open intent, or Android share intent.
- Choose the import format per CSV: Question/Answer or Cloze.
- For Question/Answer, one selected field is the front/question and every other field is shown on the back.
- For Cloze, one selected field contains Anki cloze syntax such as `{{c1::answer}}`; other fields are back-side extra content.
- Review cards by tapping to flip, swiping left for Again, swiping right for Good, or using neutral arrows to move previous/next without grading.
- Edit, delete, restore, rename, restart, export, and full app backup/restore are all local-only.

Non-goals for the current version:

- No accounts.
- No sync.
- No cloud storage.
- No LLM cleanup inside the app.
- No true spaced-repetition scheduler. Learned/Again is a lightweight review state, not Anki scheduling.

## Data Model

SQLite database file:

- Android and desktop use `path_provider` documents directory.
- The current filename is `preanki.db` for upgrade continuity. Do not rename it without a migration plan.

Tables:

- `sessions`
  - `title`, `source`
  - `field_names`: JSON list of all field names from import.
  - `front_field`: the selected question/cloze field.
  - `reveal_fields`: JSON list of fields shown on the card back.
  - `export_fields`: JSON list of export order.
  - `include_header`: whether export includes headers.
  - `total_cards`, `review_index`, timestamps.
- `cards`
  - `session_id`, `original_index`
  - `fields_json`: JSON object of field name to content.
  - `status`: `kept` or `deleted`.
  - `review_state`: `new`, `again`, or `learned`.
  - timestamps.
- `app_settings`
  - Currently stores `default_export_folder`.

Schema version:

- Current database version is `5`.
- Version 5 removed the old presets table from active schema. Repository backup/import still strips legacy `preset_id` for compatibility with old backups/databases.

Backup format:

- `format`: `llm_recall_backup`
- `formatVersion`: `1`
- `databaseVersion`: current DB schema version
- `sessions`: session rows plus cards
- `settings`: settings rows

## Import Flow

1. `ImportScreen` receives text from file picker, clipboard, or `ImportBridge`.
2. `CsvTools.parse` normalizes line endings, parses with comma/semicolon/tab, chooses the best delimiter, normalizes row widths, and detects whether the first row is likely a header.
3. The user confirms header behavior, sets a session title, chooses Question/Answer or Cloze, and checks one primary field.
4. Field names are normalized to be unique.
5. Validation rules:
   - Every field must have a name.
   - Field names must be unique.
   - Question/Answer needs at least two fields.
   - Cloze requires the selected cloze field to contain `{{c1::...}}`-style text in at least one row.
6. `AppState.createSessionFromImport` converts rows to card field maps and asks `Repository.createSession` to persist them.

There are no saved import presets by design. Each CSV can have a different shape.

## Review Flow

`AppState.nextReviewCard` selects from the review queue:

- kept cards only
- not learned
- first card with `originalIndex >= session.reviewIndex`, wrapping to the first available card when needed

Actions:

- Tap card: flip front/back only.
- Swipe left or Again button: set card `review_state = again`, advance review index to next original row.
- Swipe right or Good button: set card `review_state = learned`, advance review index.
- Delete: set card `status = deleted`, advance review index.
- Undo: restores the last graded/deleted card state and previous review index.
- Neutral arrows: move `review_index` backward/forward within the current review queue without changing `review_state`, `status`, or undo history.
- Restart: sets all kept cards back to `new` and review index to `0`.

Cards tab:

- Shows full front/back content without review pressure.
- Supports filters: All, Kept, Learning, Learned, Deleted.
- Allows edit, delete, and restore.

## Cloze Rendering

Cloze syntax is handled by `ClozeTools`.

- `questionText`: replaces each cloze with `[ hint ]` when a hint exists or `[ ... ]` otherwise.
- `answerText`: plain-text answer replacement, mainly for tests and simple transformations.
- `answerHtml`: replaces only the hidden cloze span with `<strong style="color:#12805C;font-weight:800">answer</strong>`.

Review/card text styles are intentionally regular weight. The cloze answer span is the only bold green emphasis, so the eye can jump to the answer quickly.

If future work needs full Anki cloze support:

- Add support for selecting a specific cloze number (`c1`, `c2`, etc.) as separate cards.
- Preserve current v1 behavior for one-row-one-card imports unless there is an explicit migration.

## HTML Rendering

All card field display goes through `HtmlCardText`.

- Plain text is escaped and newlines become `<br>`.
- Existing HTML is passed to `flutter_widget_from_html_core`.
- Images and tables get defensive max-width/table styles.

Do not replace this with raw `Text` for card content unless the field is guaranteed to be plain text.

## Android Import Integration

File-open and share behavior has two halves:

- Manifest intent filters in `AndroidManifest.xml` make the app appear for CSV/text files.
- `MainActivity.kt` reads `ACTION_VIEW`/`ACTION_SEND`, converts content streams to UTF-8 text, and sends a payload through MethodChannel `llm_recall/imports`.

Dart receives the payload in `ImportBridge`, then `main.dart` opens `ImportScreen` with the incoming CSV text.

Stability notes:

- Keep `android:exported="true"` for the main activity because it has launcher and external intent filters.
- Keep `launchMode="singleTop"` so new imports can reach the existing activity through `onNewIntent`.
- If binary/non-UTF-8 CSV support is needed later, add encoding detection in Kotlin/Dart before parsing.

## Export And Backup

CSV export:

- `ExportService.buildSessionCsv` exports only cards passed to it.
- `AppState.exportSession` passes only kept cards.
- Export order follows `session.exportFields`.
- Header row follows `session.includeHeader`.
- Android/iOS use `FilePicker.saveFile` bytes.
- Desktop writes selected files directly after `saveFile` returns a path.

Default export folder:

- Stored in `app_settings`.
- If configured and writable on desktop, export writes directly there.
- If stale/unwritable, the code falls back to the save picker.

Full app backup:

- JSON export/import in settings.
- Import replaces all local sessions/cards/settings.
- Backup restore is intentionally strict about `format`.

## Stability And Maintenance Rules

Do:

- Keep all persistent data local unless the product explicitly changes.
- Add migrations whenever the database schema changes.
- Keep Android app id `com.preanki.preanki` unless you are prepared to lose upgrade continuity or ship a migration strategy.
- Keep the database filename unless you migrate/copy existing data.
- Keep import/export code platform-aware: Android/iOS often use bytes, desktop often uses file paths.
- Add focused tests for every data migration and review-state behavior change.
- Run analyze, tests, and release build before handoff.

Avoid:

- Reintroducing import presets. The current product decision is per-CSV mapping.
- Treating Good/Again as spaced-repetition scheduling.
- Hand-parsing CSV; use `csv` package through `CsvTools`.
- Rendering card HTML with raw `Text`.
- Deleting old migration compatibility code just because old fields are no longer visible.

## Known Audit Notes

- Direct dependencies were checked with `dart pub outdated`; they are up to date as of this handoff.
- Flutter release builds currently warn that `file_picker` applies Kotlin Gradle Plugin. The dependency is up to date, so track future `file_picker` releases and Flutter built-in Kotlin migration notes.
- Release builds currently use debug signing in `android/app/build.gradle.kts`. Configure a private release keystore before store distribution.
- Windows runner is scaffolded and product metadata says LLM Recall. Actual Windows release builds still require the standard Flutter Windows toolchain.
- The internal Dart class names still use `PreAnki*` in places for continuity. The visible app name is LLM Recall.
